# Security

glassbrain renders data it did not write: graphs from agents and other tools, markdown in node
descriptions, html pages generated by the CLI that people send to each other. A way to run script
or exfiltrate data through any of that is a security bug.

**Please report it privately**, through GitHub's
[private vulnerability reporting](https://github.com/voidixyn/glassbrain/security/advisories/new),
not in a public issue. Include a graph file that reproduces it. You will get an answer within a
week; fixes go out as a patch release with credit, unless you prefer otherwise.

What the library already guarantees (and what a report would break):

- HTML in node data is shown as text; `javascript:` and other non-http(s) links are not links.
- Data inlined into generated pages cannot close the script tag it lives in.
- The generated page makes no requests of its own. Images that node descriptions link to do load
  from their URLs, as in any markdown viewer.
- A search written as `/regex/` runs on the viewer's own machine; a host that fills the query from
  a URL should treat it as untrusted input.
